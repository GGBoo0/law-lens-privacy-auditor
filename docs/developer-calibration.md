# 개발자 사전 교정 안내

이 기능은 분석기가 자주 틀리는 부분을 개발자가 직접 찾아 고치기 위한 작업 도구입니다. 전문가 평가를 대신하지 않으며, 여기서 나온 비율을 서비스의 법률 판단 정확도라고 공개해서는 안 됩니다.

## 무엇을 검토하나요?

표본은 총 24개입니다. 한 업종에 치우치지 않도록 다음 6개 업종에서 4개씩 검토합니다.

- 전자상거래
- 금융
- 온라인 플랫폼·콘텐츠
- 통신·이동·숙박
- 의료·건강
- 교육·아동

사이트명과 주소는 내보내는 교정 파일에 저장하지 않습니다. 화면에서는 같은 회사를 여러 번 넣지 않도록 `쇼핑 A` 같은 별칭을 붙일 수 있지만, 이 별칭은 현재 브라우저에만 남고 내보내기에서는 빠집니다.

분석기가 표시한 각 지적은 다음 세 가지 중 하나로 선택합니다.

- `확인됨`: 실제로 검토할 만한 지적입니다.
- `오탐`: 처리방침에 내용이 있는데 잘못 경고했거나, 적용되지 않는 규칙입니다.
- `판단 유보`: 문서만으로는 확실히 결정하기 어렵습니다.

또한 근거 문구가 해당 지적을 뒷받침하는지, 연결한 법 조항이 적절한지, 분석기가 놓친 지적이 있는지도 따로 기록합니다. 오탐과 판단 유보에는 자유로운 메모 대신 정해진 사유 코드만 사용합니다.

## 원문을 왜 저장하지 않나요?

교정 파일에는 개인정보처리방침 본문, 문장 인용, HTML, 회사명, 도메인, URL을 넣지 않습니다. 다음 정보만 남깁니다.

- 문서를 다시 확인할 수 있는 SHA-256 해시
- 근거가 있던 글자 위치와 해당 부분의 해시
- 사용한 분석기·규칙 목록·앱에 포함된 법령 기준 파일의 버전 해시
- 각 분석에 실제 사용된 실시간 법령 상태와 법령 기준일의 해시
- 분석 결과에 표시된 분석기 버전과 규칙셋 버전
- 검토 판정과 정해진 사유 코드

분석기가 처음 만든 지적 개수도 함께 고정합니다. `검토 중`에는 확인한 항목까지만 안전하게 저장할 수 있지만, `완료`로 바꿀 때는 판정 개수가 처음 지적 개수와 정확히 같아야 합니다. 따라서 미검토 항목을 `판단 유보`로 미리 채울 필요가 없습니다.

가져오기와 내보내기 전에 같은 검증기를 실행합니다. 금지된 필드, 중복 사례, 중복 문서, 가짜 해시, 잘못된 집계가 하나라도 있으면 파일 전체를 거부합니다. 잘못된 항목만 조용히 빼고 계속 진행하지 않습니다.
새 분석 결과를 슬롯에 넣을 때도 분석기 버전과 규칙셋 버전이 데이터셋에 고정된 값과 같은지 확인합니다. 버전이 다르면 서로 다른 규칙의 결과를 한 집계에 섞지 않고 새 교정 데이터셋을 시작합니다.

첫 표본을 넣을 때는 분석에 실제 영향을 준 법령 상태를 한 묶음으로 고정합니다. 공식 확인 시각만 바뀌고 판단 기준이 같다면 계속 검토할 수 있습니다. 반대로 새 법령이 시행되는 등 판단 기준이 바뀌면 기존 표본과 섞지 않고 새 교정 묶음을 시작합니다. 법령 상태가 오래됐거나 유효하지 않은 분석 결과는 주 사전 교정 표본으로 받지 않습니다.

## 문서 전체 여부가 중요한 이유

처리방침 일부만 확보했다면, 보이지 않는 부분에 필요한 내용이 있을 수 있습니다. 따라서 각 표본에 다음 두 항목을 반드시 표시합니다.

- 문서 상태: 전체·일부·확인 불가
- 누락 여부를 끝까지 확인했는지

사람이 찾은 누락은 `누락 확인 완료`인 표본에서만 기록할 수 있습니다. 누락 관련 비율은 전체 문서를 확보하고 누락 확인까지 끝낸 표본만 분모로 사용합니다.
전체 문서를 확보한 표본은 누락 확인까지 끝내야 `완료`로 바꿀 수 있습니다. 일부 문서 표본은 다른 지적을 검토한 뒤 완료할 수 있지만 누락 관련 비율에서는 제외됩니다.

## 화면에 보이는 숫자의 뜻

화면의 숫자는 모두 **사전 교정 건수 또는 사전 교정 비율**입니다.

- 완료율: 24개 중 검토를 마친 표본의 비율
- 확인 비율: 분석기 지적 중 개발자가 확인한 비율
- 오탐 비율: 분석기 지적 중 잘못된 경고로 표시한 비율
- 판단 유보 비율: 바로 결정하지 못한 지적의 비율
- 근거 문구·법 조항 지원 비율: 연결된 근거가 적절하다고 표시한 비율
- 누락 발견 표본 비율: 전체 문서와 누락 확인을 완료한 표본 중 사람이 추가 누락을 찾은 비율

표본이 아직 없으면 비율은 `0%`가 아니라 `평가 전`으로 표시합니다. 이 숫자는 한 명의 개발자가 개선 방향을 찾기 위한 참고값이며, 전문가 2인의 독립 검토와 의견 조정을 거친 인증 결과가 아닙니다.

## 데이터 버전과 변경 규칙

- `schemaVersion`: 파일 구조 버전
- `aggregateVersion`: 집계 계산 방식 버전
- `datasetRevision`: 검토 내용이 바뀔 때 올리는 번호
- `reviewMode`: 항상 `developer_self_review`
- `validationLevel`: 항상 `not_expert_validated`

구조나 계산 방식이 달라지면 해당 버전을 올립니다. 단순히 검토 판정 하나를 수정했다면 `datasetRevision`을 올리고 집계를 다시 계산합니다. 내보낸 파일의 집계가 원본 기록에서 다시 계산한 값과 다르면 가져오기를 차단합니다.

## 전문가 평가와의 관계

사전 교정 데이터는 제품을 개선할 때만 사용하며, 전문가 평가 데이터와 합치지 않습니다. 나중에 전문가 평가를 시작하더라도 이 24개 표본을 인증용 시험 표본으로 재사용하지 않는 것이 좋습니다. 개발 중 이미 본 사례를 시험에 쓰면 결과가 실제보다 좋아질 수 있기 때문입니다.
